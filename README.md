# Campus-Repair-Assistant

校园快修服务助手

## 项目简介

校园快修的统一入口 + 智能调度中枢——学生一句话 + 一张照片完成报修，系统自动理解故障、分流自助解决或派单、全程跟踪，并把每次维修沉淀为知识资产。

## 核心功能

- **智能报修**：文字 + 拍照描述故障，多模态理解后自动补全楼栋、预约时间、紧急度等字段，生成结构化工单
- **自助诊断**：基于维修知识库（维修手册 + 历史工单）的 RAG 问答，如"路由器亮红灯怎么办"，能自修就分流
- **调度 Agent**：按故障类别、位置、师傅排班与时间窗自动匹配派单，冲突检测，支持改约
- **进度跟踪**：状态机全流程通知（提交/接单/上门/待验收/完成），支持取消、改约
- **评价与知识沉淀**：完成后的评分与维修结论，清洗后回流知识库，持续提升诊断准确率
- **运营看板**：维修量、平均响应/完成时长、满意度、高频故障 Top 榜

## 技术栈

- **前端**：Vue 3 + Vite + Element Plus + ECharts
- **后端**：Spring Boot + JPA + MySQL
- **AI**：大语言模型 API 接入（多模态理解 + RAG 问答）

## 快速开始

### 前端
```bash
cd frontend
npm install
npm run dev
```

### 后端
```bash
cd backend
mvn spring-boot:run
```

## 开发规范

- 每人负责一个功能模块（前后端都由本人完成）
- 在 `feature/功能名` 分支上开发
- 完成后发起 Pull Request 合并到 main

## 团队分工

> 分工原则：每人负责一个功能模块（前后端均由本人完成）；组长承担调度模块并统筹全项目，难度按修正后口径标注。

| 成员 | 负责功能 | 难度 | 备注 |
|------|----------|:----:|------|
| 开璐瑶（组长） | 调度 Agent（自动派单、冲突检测、改约） | ★★★ | 兼整体联调 / Docker 部署 / 文档 / 答辩 |
| 闵娟 | 自助诊断（RAG 问答、维修知识库） | ★★★★ | RAG 检索链路主程（Chroma / Embedding / 阈值调优）；知识库后台由伍梦圆协助 |
| 杨思彤 | 进度跟踪 + 评价体系（状态机、评价与知识回流） | ★★★ | 兼通知消息；知识回流产生"候选"，入库审核对接伍梦圆 |
| 钟心茹 | 运营看板 + 用户体系（三类角色、排班、统计图表） | ★★★ | JWT 认证模板最先交付、全组共用；兼故障类别管理 |
| 伍梦圆 | 智能报修（文字+拍照多模态理解、工单生成） | ★★ | 兼 AI 公共封装（模型代理/提示词模板/密钥用量）与知识库后台（CRUD+审核页） |

### 职责边界

- 管理端：导航/框架/权限归钟心茹；知识库审核页归伍梦圆（页面挂在管理端、接口归伍梦圆）。
- 排班数据：CRUD 归钟心茹，调度只读（不写排班）。
- 知识回流：杨思彤只生成候选；入库/审核由伍梦圆完成（`knowledge_base` 状态 PENDING → APPROVED）。
- AI 模型代理：伍梦圆统一封装一份，多模态与 RAG 共用。
