# 组员真实短信与邮箱配置指南

## 1. 为什么不提交真实授权码

本仓库是公开仓库。SMTP 授权码、Spug 模板令牌、数据库密码一旦提交，任何访问仓库的人都能看到，并可能被自动扫描工具抓取，导致短信额度被盗用。

因此：

- 配置模板提交到 Git。
- 每台电脑在本机生成真实配置文件。
- 真实配置文件被 `.gitignore` 忽略。
- 真实值通过组内私聊、共享文档等非公开方式分发。

## 2. 新电脑首次配置

```powershell
cd backend/scripts
.\setup-local-config.ps1
```

按提示输入：

1. 邮箱账号
2. SMTP 授权码
3. 发件邮箱，直接回车则默认与登录邮箱一致
4. Spug 短信模板完整地址

脚本会生成：

```text
backend/src/main/resources/application-local.properties
```

该文件已被 `.gitignore` 忽略。

## 3. 启动项目

```powershell
cd backend
$env:JAVA_HOME='C:\Program Files\Java\jdk-17'
mvn spring-boot:run
```

启动后，邮箱和短信会读取本机的真实配置，不会返回 `mockCode`。

## 4. Spug 注意事项

- Spug 控制台必须有可用短信额度。
- 当前网络公网出口 IP 必须加入 Spug 模板 IP 白名单。
- 使用手机热点时公网 IP 可能变化，需要重新添加。
- 额度不足和 IP 白名单错误会在登录页显示不同提示。

## 5. SMTP 注意事项

- QQ 邮箱使用 `smtp.qq.com:465` 和 SSL。
- SMTP 密码是邮箱授权码，不是网页登录密码。
- SMTP 认证失败会显示“邮箱服务认证失败”。
- 发件邮箱通常必须与 SMTP 登录账号一致。
- 建议正式环境配置 SPF、DKIM、DMARC。

## 6. 检查配置是否生效

发送邮箱验证码后，接口响应不应包含 `mockCode`。

正常响应示例：

```json
{
  "code": 200,
  "message": "验证码已发送",
  "data": {}
}
```

如果仍然显示模拟验证码，说明启动的旧后端进程没有加载本地配置，需要停止旧进程并重新启动。
