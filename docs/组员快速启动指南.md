# 组员快速启动指南（Windows 本机开发，一条龙从零到跑通）

> 目标：克隆仓库后 20 分钟内看到页面并完成一次文件上传。
> 遇到报错先跳到文末「7. 常见坑」；本文假定 Windows（macOS/Linux 组员大步骤相同）。

## 0. 前置清单（只装这四样）

| 必备项 | 版本 | 安装要点 |
|---|---|---|
| JDK | **25**（Temurin 25.0.5+ LTS） | 装完设环境变量 `JAVA_HOME` 指向安装目录（如 `E:\JavaService\JDK25`），别只想了 PATH，Maven 认 `JAVA_HOME` |
| Docker Desktop | 最新版 | 装完启动一次并等托盘图标变绿；需要 WSL2 |
| Node.js | 18+ | 官网安装器一路下一步 |
| Maven | 可选 | **backend 里自带 `mvnw.cmd`，不装也能跑**（见第 4 步）；上面脚本用 `mvn` 的才需要装 |

## 1. 克隆仓库

```powershell
git clone <仓库地址>
cd Campus-Repair-Assistant-main
```

## 2. MinIO（文件存储容器）——注意：官方 Hub 已停更，必须从组内拿镜像！

Getty官方 `minio/minio` 镜像 **已无法 docker pull**（社区版 2026 年 9 月从 Docker Hub 整库移除）。两条路径二选一：

```powershell
# 路径 A（推荐）：向组内（群文件/云盘）拿 minio-campus.tar，然后：
docker load -i .\minio-campus.tar

# 路径 B：从 quay.io 直接拉归档冻结版（比 A 方便，但依赖外网）
docker pull quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z
```

然后一条命令起容器（直接抄，等号和引号都别动）：

```powershell
docker run -d --name campus-minio --restart unless-stopped `
  -p 127.0.0.1:9000:9000 -p 127.0.0.1:9001:9001 `
  -v campus-minio-data:/data `
  -e MINIO_ROOT_USER=admin -e MINIO_ROOT_PASSWORD=ChangeMe_123 `
  minio/minio:RELEASE.2025-09-07T16-13-09Z `
  server /data --console-address ":9001"
```

自检：浏览器开 `http://localhost:9001`，用 `admin / ChangeMe_123` 能登进控制台即 OK。
**桶不用建**：后端第一次收到上传请求时会自动检查并创建 `campus-repair` 桶。

## 3. MySQL 主从（读写分离演示的另一半）

```powershell
cd deploy\docker
docker compose up -d
docker ps          # 等 mysql-master / mysql-slave 都显示 (healthy)，约 20~40 秒
cd ..\..
```

> 数据库 `campus_repair` 和 15 张表由容器首次启动自动初始化，**请勿删除首次初始化的日志**；
> 如果起不来，99% 是 3306/3307 端口被本机其他 MySQL 占用——见「常见坑」第 4 条。

## 4. .env（密码文件，自建，永不提交）

仓库根目录新建 `.env`，只写两行（密码与第 3 步 compose 默认一致）：

```
DB_USERNAME=root
DB_PASSWORD=ChangeMe_123
```

> 注意：`.env` 已在 `.gitignore` 里，`git clone` 后你本地是没有的，必须自己建。
> 文件服务不需要写任何东西——MinIO 账号在配置里有默认值。

## 5. 启动后端

```powershell
# 方式 A（推荐）：仓库自带 Maven 包装器，不要求本机装过 Maven
cd backend
.\mvnw.cmd spring-boot:run

# 方式 B：用仓库的一键脚本（需要本机装过 Maven 并配置 JAVA_HOME）
powershell -ExecutionPolicy Bypass -File .\scripts\run-backend.ps1
```

看到 `Started CampusRepairApplication in X seconds` 即成功，Tomcat 在 **8080**。
自检：

```powershell
curl http://localhost:8080/api/system/node
# 期望返回 {"hostname":"...","localPort":8080,...}
```

## 6. 启动前端 + 端到端验收

```powershell
cd frontend
npm install        # 首次较慢，耐心
npm run dev        # Vite 起在 5173，/api 自动转发到 8080
```

浏览器开 **http://localhost:5173** → 文件管理页：

1. **小文件**：填个工单ID → 选 2~3 个文件 → 批量上传 → 提示成功
2. **大文件**：填工单ID → 选一个 >5MB 的文件 → 分片上传 → 进度条走完提示合并成功
3. 右侧工单附件输同一个工单ID → 查询 → 两个文件都在 → 试试单个下载和 ZIP 打包
4. 想肉眼看文件本体：`http://localhost:9001` → Object Browser → `campus-repair` → `uploads/`

## 7. 常见坑（按报错对号入座）

| # | 现象 | 原因与解法 |
|---|---|---|
| 1 | `mvn` 报"不支持发行版本 25" | `JAVA_HOME` 没设对（指到 JDK 25 目录），或在旧终端里设置过就重开终端；`.\mvnw.cmd -v` 看 `Java version` 是否 25 |
| 2 | 后端启动即崩：`Communications link failure` / `Unable to determine Dialect` | MySQL 没起。回第 3 步 `docker compose up -d`，确认 healthy 再启后端 |
| 3 | 上传接口返回 503 "MinIO 未配置" | `campus-minio` 容器没起来。`docker start campus-minio`；`file.minio.*` 配置在 `backend/src/main/resources/application.properties` 里有默认值，通常不用动 |
| 4 | `docker compose up` 报端口冲突 | 本机已有别的 MySQL 占了 3306/3307（看 `netstat -ano | findstr "3306 3307"`），或 Docker Desktop 没启动 |
| 5 | `docker run` 报 `pull access denied`（minio 镜像） | 拉不到是正常的（官方已停更）。回到第 2 步走 `docker load` |
| 6 | 前端 5173 能开但接口全 502/proxy error | 后端没起或 8080 被占（看第 5 步日志）；`netstat -ano | findstr :8080`。重启后端即可 |
| 7 | 上传报"分片会话不存在" | 后端重启过，且旧会话没挂库（极少见，新实现已把会话落库）；重传一次即可 |
| 8 | 端口默认值速记 | MinIO S3=9000、控制台=9001、主库=3306、从库=3307、后端=8080、前端=5173 |

## 8. 每天开工的标准三连（老手速查）

```powershell
docker start campus-minio mysql-master mysql-slave   # 三个容器
cd backend; .\mvnw.cmd spring-boot:run               # 后端
cd frontend; npm run dev                             # 前端
```

数据都在 Docker 卷里（`campus-minio-data`、`master-data`、`slave-data`），`docker start` 即恢复，
**不要** `docker compose down -v`（会连数据卷一起删，文件和记录全没）。
