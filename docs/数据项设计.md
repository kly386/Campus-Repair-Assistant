# 数据项设计

> 校园快修服务助手 —— 系统核心数据项定义  
> 版本：v1.4  
> 说明：严格遵循《阿里巴巴 Java 开发手册》MySQL 建表规约。已统一表必备三字段（id、gmt_create、gmt_modified）、布尔字段命名（is_xxx）、小数类型（DECIMAL）、禁止物理外键。共 15 张业务表，与 `init.sql` 和 `backend` 实体代码对应。

---

## 1. 实体总览

| 实体 | 中文名 | 所属功能 | 说明 |
|------|--------|----------|------|
| User | 用户 | 全角色 | 学生 / 师傅 / 管理员三类角色统一管理 |
| WorkerSpecialty | 师傅专长 | 调度 | 师傅擅长类别，多对多关联故障类别 |
| RepairCategory | 故障类别 | 智能报修 / 基础配置 | 故障分类，含“是否可自助解决”标记 |
| RepairOrder | 报修工单 | 智能报修 / 进度跟踪 | 核心业务实体，派单字段内嵌 |
| RepairOrderAttachment | 工单附件 | 智能报修 | 工单的图片、视频等附件 |
| OrderStatusLog | 状态流转日志 | 进度跟踪 | 工单状态变更记录 |
| DiagnosisSession | 诊断会话 | 自助诊断 | RAG 问答会话记录 |
| KnowledgeBase | 知识库 | 自助诊断 | 维修手册 + 历史结论 |
| KnowledgeHistory | 知识库历史 | 自助诊断 | 知识条目修改历史，支持回滚 |
| WorkerSchedule | 师傅排班 | 调度 | 师傅可服务时间、区域与负载 |
| Assignment | 派单记录 | 调度 | 每次派单尝试的记录，含成功与失败 |
| OrderEvaluation | 服务评价 | 评价与沉淀 | 工单完成后的评分与评价 |
| Notification | 通知消息 | 通知 | 站内通知 |
| AuditLog | 操作日志 | 系统管理 | 管理员关键操作审计 |
| SystemConfig | 系统配置 | 基础配置 | 派单权重、相似度阈值等可配置参数 |

> 说明：
> 1. 旧 `Worker` 合并进 `User`，师傅专长改用 `worker_specialty` 表关联。
> 2. 旧 `Schedule` 改为 `worker_schedule`。
> 3. 旧 `Assignment` 恢复为独立表，记录派单历史，便于分析。
> 4. 旧 `Evaluation` 改为 `order_evaluation`。
> 5. 旧 `KnowledgeItem` 改为 `knowledge_base`，并增加 `knowledge_history`。
> 6. 新增 `repair_order_attachment`、`audit_log`、`system_config`。
> 7. 所有表遵循：表名小写下划线、单数；必备三字段 `id`、`gmt_create`、`gmt_modified`；布尔字段 `is_xxx`；小数用 `DECIMAL`；禁止物理外键。

## 3. 状态机定义

### 3.1 工单状态（RepairOrder.status）

| 状态 | 中文名 | 说明 |
|------|--------|------|
| SUBMITTED | 待派单 | 学生已提交，等待调度 Agent 派单 |
| ASSIGNED | 已派单 | 已匹配到师傅，等待师傅接单 |
| ON_THE_WAY | 上门中 | 师傅已接单，正在赶往现场 |
| PROCESSING | 处理中 | 师傅正在维修 |
| PENDING_ACCEPT | 待验收 | 师傅维修完毕，等待学生确认 |
| COMPLETED | 已完成 | 学生确认验收（终态） |
| CANCELLED | 已取消 | 工单被取消（终态） |
| RESCHEDULED | 已改约 | 改约中间态，由已派单进入，改约后触发重新派单 |

### 3.2 允许的状态流转

| 原状态 | 允许流转到 |
|--------|-----------|
| SUBMITTED | ASSIGNED, CANCELLED |
| ASSIGNED | ON_THE_WAY, CANCELLED, RESCHEDULED |
| ON_THE_WAY | PROCESSING, CANCELLED |
| PROCESSING | PENDING_ACCEPT, CANCELLED |
| PENDING_ACCEPT | COMPLETED, PROCESSING（驳回返修） |
| COMPLETED | ——（终态） |
| CANCELLED | ——（终态） |
| RESCHEDULED | ASSIGNED（重新派单成功）、SUBMITTED（重新派单失败）、CANCELLED |

| ScheduleStatus | FREE / BUSY / REST | 排班状态 |
| UserStatus | ACTIVE / DISABLED | 用户状态 |
| KnowledgeSource | MANUAL / ORDER | 知识来源 |
| ReviewStatus | PENDING / APPROVED / REJECTED / OFFLINE | 知识审核状态 |
| NotificationType | ORDER_STATUS / SYSTEM / REMIND | 通知类型 |
| Category | WATER_ELECTRIC / NETWORK / FURNITURE / OTHER | 兼容旧枚举，建议存入 `repair_category.code` |

## 5. 数据流简述

1. **报修**：学生提交 → AI 多模态理解 → 补全 `category_id / building / room / emergency_level` → 生成 `RepairOrder`（`SUBMITTED`）→ 写 `OrderStatusLog` → 保存附件到 `RepairOrderAttachment` → 触发派单。
2. **诊断分流**：学生提问 → RAG 检索 `knowledge_base` → 命中且高相似度 → 返回带引用来源答案 → 若 `is_solved=1` 则不派单，记录 `DiagnosisSession`。
3. **派单**：调度读取 `RepairOrder + User(师傅) + WorkerSchedule + WorkerSpecialty` → 过滤冲突与负载 → 加权打分选师傅 → 更新 `RepairOrder.worker_id / assign_score / assign_reason / status=ASSIGNED` → 写 `Assignment` 记录 → 更新排班 `cur_orders` → 写 `Notification`。
4. **进度**：师傅每次操作 → 校验状态机合法性 → 更新 `status + version` → 写 `OrderStatusLog` → 推送通知。
5. **评价**：工单 `COMPLETED` → 学生提交 `OrderEvaluation` → 评分 ≥ 4 且 `repair_order.result` 非空 → 知识候选 → 管理员审核 → 入 `knowledge_base`，`source=ORDER`，记录 `source_order_id`，同时写 `KnowledgeHistory`。
6. **看板**：从 `repair_order + order_evaluation` 聚合统计维修量、时长、满意度、高频故障 Top 榜。
7. **审计**：管理员关键操作写入 `AuditLog`；系统配置从 `SystemConfig` 读取。

## 6. 与代码的对应关系

- 实体类：`backend/src/main/java/com/example/campusrepair/entity/`
- 数据访问：`backend/src/main/java/com/example/campusrepair/repository/`
- 数据库表名：小写下划线，如 `repair_order`、`order_status_log`、`worker_schedule`、`knowledge_base`、`order_evaluation`、`notification`、`repair_order_attachment`、`audit_log`、`system_config`、`worker_specialty`、`knowledge_history`、`assignment`
- 字段名：小写下划线，如 `gmt_create`、`student_id`、`emergency_level`、`appointment_time`
- 注意：`Worker` 不再单独建表，师傅是 `user.role = WORKER`，专长在 `worker_specialty` 表。
- **严格禁止物理外键**，所有关联关系在应用层维护。
- 所有表必备三字段：`id`、`gmt_create`、`gmt_modified`。
- 布尔字段统一 `is_xxx`，类型 `TINYINT(1) UNSIGNED`。
- 小数统一 `DECIMAL`，禁止 `FLOAT` / `DOUBLE`。
- 索引命名建议：主键 `pk_id`，唯一索引 `uk_字段名`，普通索引 `idx_字段名`。
