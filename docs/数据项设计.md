## 3. 状态机定义

### 3.1 工单状态（RepairOrder.status）
待派单(PENDING)
│
├──► 已派单(ASSIGNED) ──► 处理中(PROCESSING) ──► 待验收(TO_VERIFY) ──► 已完成(FINISHED)
│
└──► 已取消(CANCELLED) （任意状态均可取消，已完成除外）

### 3.2 允许的状态流转（幂等校验用）

| 原状态 | 允许流转到 |
|--------|-----------|
| PENDING | ASSIGNED, CANCELLED |
| ASSIGNED | PROCESSING, CANCELLED |
| PROCESSING | TO_VERIFY, CANCELLED |
| TO_VERIFY | FINISHED, PROCESSING（驳回返修） |
| FINISHED | —— |
| CANCELLED | —— |

## 5. 数据流简述

1. **报修**：学生提交 → AI 多模态理解 → 补全 category/building/urgency → 生成 RepairOrder（PENDING）→ 写 OrderStatusLog
2. **诊断分流**：学生提问 → RAG 检索 KnowledgeItem → 命中且高相似度 → 返回答案 → 若 is_solved=true 则不派单
3. **派单**：调度 Agent 读取 RepairOrder + Worker + Schedule → 打分选师傅 → 写 Assignment → 更新 RepairOrder（ASSIGNED）
4. **进度**：师傅每次操作 → 校验状态机合法性 → 更新 status + 写 OrderStatusLog
5. **评价**：工单 FINISHED → 学生提交 Evaluation → 评分≥4 且结论非空 → 管理员审核 → 入 KnowledgeItem
6. **看板**：从 RepairOrder + Evaluation 聚合统计
