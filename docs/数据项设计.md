# 数据项设计

> 校园快修服务助手 —— 系统核心数据项定义
> 版本：v1.1
> 说明：本文档定义系统所有核心实体及其字段，与 `docs/sql/init.sql`、`docs/需求分析.md` 保持一致，作为数据库设计、接口设计、AI 提示词设计的基础。

---

## 1. 实体总览

共 9 张业务表，与 `init.sql` 一一对应。

| 实体 | 中文名 | 所属功能 | 说明 |
|------|--------|----------|------|
| User | 用户 | 全角色 | 学生 / 师傅 / 管理员；师傅档案（专长）也存本表 |
| RepairCategory | 故障类别 | 智能报修 / 自助诊断 | 多级分类，可自助解决标记 |
| RepairOrder | 报修工单 | 智能报修 | 核心业务实体；派单结果（得分/理由）直接存本表 |
| OrderStatusLog | 状态流转日志 | 进度跟踪 | 工单状态变更记录 |
| DiagnosisSession | 自助诊断会话 | 自助诊断 | 一次 RAG 问答 |
| KnowledgeBase | 知识库条目 | 自助诊断 | 维修手册 + 工单沉淀 |
| WorkerSchedule | 师傅排班 | 调度 | 可服务时间窗与当前负载 |
| OrderEvaluation | 服务评价 | 评价与沉淀 | 工单完成后的评分与评论 |
| Notification | 通知消息 | 进度跟踪 | 状态变更等通知 |

> 设计说明：不再单独设计派单记录（Assignment）表，派单得分与决策理由落 `repair_order.assign_score / assign_reason`，与 `init.sql` 保持一致。

## 3. 状态机定义

### 3.1 工单状态（RepairOrder.status）

```
已提交(SUBMITTED)
   │
   ├──► 已派单(ASSIGNED) ──► 上门中(ON_THE_WAY) ──► 处理中(PROCESSING) ──► 待验收(PENDING_ACCEPT) ──► 已完成(COMPLETED)
   │
   ├──► 已取消(CANCELLED)（任意状态均可取消，已完成除外）
   │
   └──► 改约(RESCHEDULED) ──► 已派单(ASSIGNED，重新派单成功)
                              ├──► 已提交(SUBMITTED，重新派单失败)
                              └──► 已取消(CANCELLED，学生放弃)
```

### 3.2 允许的状态流转（幂等校验用）

| 原状态 | 允许流转到 |
|--------|-----------|
| SUBMITTED | ASSIGNED, CANCELLED |
| ASSIGNED | ON_THE_WAY, CANCELLED, RESCHEDULED（改约） |
| ON_THE_WAY | PROCESSING, CANCELLED |
| PROCESSING | PENDING_ACCEPT, CANCELLED |
| PENDING_ACCEPT | COMPLETED, PROCESSING（驳回返修） |
| COMPLETED | ——（终态） |
| CANCELLED | ——（终态） |
| RESCHEDULED | ASSIGNED（重新派单成功）、SUBMITTED（重新派单失败）、CANCELLED |

## 5. 数据流简述

1. **报修**：学生提交（携带 idempotency_key 防重复）→ AI 多模态理解 → 补全 category_id/building/emergency_level/appointment_time 并写入 ai_parsed_info → 生成 RepairOrder（SUBMITTED）→ 写 OrderStatusLog
2. **诊断分流**：学生提问 → RAG 检索 KnowledgeBase → 命中且高相似度 → 返回答案并写 DiagnosisSession → is_solved=true 则不派单
3. **派单**：调度 Agent 读取 RepairOrder + User(师傅专长) + WorkerSchedule → 打分选师傅 → 更新 RepairOrder 的 worker_id/assign_score/assign_reason 并置 ASSIGNED → 写 OrderStatusLog（不建独立派单表）
4. **进度**：每次操作 → 校验状态机合法性 → 乐观锁 version 防并发覆盖 → 更新 status + 写 OrderStatusLog
5. **评价**：工单 COMPLETED → 学生提交 OrderEvaluation(score/comment)，师傅提交维修结论存 repair_order.result → 评分≥4 且结论非空 → 管理员审核 → 入 KnowledgeBase(source=ORDER, source_order_id)
6. **看板**：从 RepairOrder + OrderEvaluation + DiagnosisSession 聚合统计
