# 校园快修服务助手：认证鉴权与验证码实现总结

> 总结日期：2026-11-17  
> 对应模块：登录认证、JWT 会话、动态 RBAC、验证码、限流反爬、Spug 短信、SMTP 邮箱、前端权限联动  
> 注意：本文不记录真实 SMTP 授权码、Spug 模板地址令牌、JWT 生产密钥等敏感信息。

---

## 1. 整体目标

本模块参考禅道的鉴权授权思想，实现“统一认证 + 动态权限 + 会话可吊销 + 接口级校验”的完整链路。

核心目标：

1. 支持账号密码、手机验证码、邮箱验证码、微信扫码四种登录方式。
2. 密码连续错误 5 次锁定账号 10 分钟，锁定期间四种方式全部禁止登录。
3. JWT 不只做前端登录状态标记，而是绑定服务端会话；账号锁定、退出、权限变更后 Token 立即失效。
4. 后端使用标准 RBAC：用户 → 角色 → 权限。
5. 前端根据后端权限动态生成路由、菜单和按钮。
6. 验证码发送有冷却、频率限制、过期时间和尝试次数。
7. 登录、发送、锁定、解锁、权限变更都有日志。
8. 支持真实 Spug 短信和真实 SMTP 邮箱，不依赖模拟模式。

- `wx_openid`：微信扫码绑定。
- `status`：`ACTIVE / LOCKED / DISABLED`。
- `token_version`：预留一次性全量吊销能力。
- `last_login_at`：最后登录时间。

### 3.2 RBAC 关系

```text
用户 user
  ↓ user_role

  ↓ role_permission

  ├── MENU：前端菜单与动态路由
  ├── API：后端接口权限
  └── BUTTON：前端按钮权限
```

权限标识示例：

```text
order:create
order:read
order:update
order:delete
file:upload
file:read
system:user:role
system:role:permission
system:user:lock
system:user:unlock
```

超级权限：

```text
*:*
```

## 4. 四种登录方式

### 4.1 账号密码登录

流程：

```text
用户名 + 密码 + 图形验证码
    ↓
校验图形验证码，一次性消费
    ↓
查询用户
    ↓
检查账号是否锁定/禁用
    ↓
BCrypt 校验密码
    ↓
错误：失败次数 +1
    ↓
连续错误达到 5 次：锁定账号 10 分钟，并吊销该用户全部 Token
    ↓
正确：清除失败计数，建立服务端会话，签发 access/refresh Token
```

接口：

```text
POST /api/auth/login
```

关键点：

- 图形验证码先校验，成功后立即删除，防止重放。
- 密码错误只在图形验证码正确后累计，避免验证码错误消耗账号失败次数。
- 明文历史密码登录成功后自动升级为 BCrypt。
- 返回 423 时包含 `lockRemainingMinutes` 和 `errorCode=ACCOUNT_LOCKED`。

### 4.2 手机验证码登录

流程：

```text
手机号
    ↓
检查手机号格式
    ↓
检查同一手机号 60 秒冷却
    ↓
检查同一 IP 每分钟次数
    ↓
生成 6 位安全随机验证码
    ↓
保存 5 分钟、最多尝试 5 次
    ↓
调用 Spug 真实短信接口
    ↓
发送成功：等待用户输入验证码
    ↓
验证码正确：登录或自动注册学生账号
```

接口：

```text
POST /api/auth/code/send
POST /api/auth/sms/login
```

统一发送请求：

```json
{
  "type": "PHONE",
  "target": "手机号"
}
```

### 4.3 邮箱验证码登录

流程：

```text
邮箱地址
    ↓
检查邮箱格式
    ↓
检查邮箱 60 秒冷却
    ↓
检查同一 IP 每分钟次数
    ↓
生成 6 位验证码
    ↓
保存 5 分钟、最多尝试 5 次
    ↓
调用 Spring Mail + SMTP 发送
    ↓
验证码正确：登录或自动注册学生账号
```

统一发送请求：

```json
{
  "type": "EMAIL",
  "target": "邮箱地址"
}
```

### 4.4 微信扫码登录

本地模拟模式：

```text
生成 uuid 和模拟二维码
    ↓
前端每 2 秒轮询
    ↓
WAITING → SCANNED → CONFIRMED
    ↓
确认后签发 Token
    ↓
二维码 3 分钟过期，前端自动刷新
```

生产模式：

```text
微信开放平台 qrconnect 授权地址
    ↓
用户扫码
    ↓
微信回调 /api/auth/wx/callback
    ↓
后端用 code 换 openid
    ↓
state 标记为 CONFIRMED
    ↓
前端轮询获取 Token
```

关键接口：

```text
POST /api/auth/wx/qrcode
GET  /api/auth/wx/state?uuid=...
GET  /api/auth/wx/callback?code=...&state=...
```

## 5. JWT 与会话吊销

### 5.1 Token 类型

- access Token：默认 30 分钟。
- refresh Token：默认 7 天。

JWT claims：

```json
{
  "iss": "campus-repair",
  "sub": "用户ID",
  "sid": "服务端会话ID",
  "jti": "令牌唯一ID",
  "type": "access 或 refresh"
}
```

### 5.2 为什么不是纯 JWT

纯 JWT 的缺点是签发后无法主动撤销。

本模块采用：

```text
JWT 签名
  +
auth_session 服务端会话
  +
jti 校验
  +
客户端指纹
  +
账号状态实时检查
```

因此：

- 用户退出登录，旧 Token 立即失效。
- 管理员锁定账号，旧 Token 立即失效。
- 修改用户角色，旧 Token 立即失效。
- 修改角色权限，该角色下用户旧 Token 立即失效。
- 账号锁定期间，即使旧 Token 未过期也无法访问接口。

### 5.3 refresh Token 轮换

每次刷新：

1. 校验 refresh JWT。
2. 校验服务端 session 和 refresh jti。
3. 生成新的 access/refresh Token。
4. 替换服务端 jti。
5. 旧 refresh Token 再次使用会判定为重放，吊销整个会话。

接口：

```text
POST /api/auth/refresh
POST /api/auth/logout
```

## 6. 仿禅道的动态 RBAC

### 6.1 后端动态权限

`PermissionService` 每次请求通过：

```text
当前用户ID
  ↓
user_role
  ↓
role_permission
  ↓
permission
```

实时得到：

- 角色集合。
- 权限 code 集合。
- MENU 类型权限树。

权限不写死在 JWT 中，避免角色/权限修改后必须等待 Token 过期。

### 6.2 接口级权限

自定义注解：

```java
@RequirePermission("order:create")
```

统一拦截器 `AuthInterceptor` 负责：

1. 校验 Authorization Bearer Token。
2. 校验 JWT 签名和过期时间。
3. 校验 token type 必须是 access。
4. 校验服务端会话未吊销。
5. 校验 jti 一致。
6. 校验客户端指纹。
7. 校验账号未锁定/禁用。
8. 实时加载用户权限。
9. 校验 `@RequirePermission`。
10. 写入请求上下文 `AuthContext`。

即使前端隐藏按钮，直接调用接口仍会返回 403。

### 6.3 菜单权限

`/api/user/me` 和 `/api/user/menus` 返回菜单树：

```json
{
  "permissions": ["menu:repair", "order:create"],
  "menus": [
    {
      "code": "menu:repair",
      "name": "智能报修",
      "path": "/repair",
      "component": "Repair",
      "icon": "Tools",
      "children": []
    }
  ]
}
```

### 6.4 前端动态路由和菜单

- `frontend/src/router/dynamicRoutes.js`：根据后端 `menus` 动态 `addRoute`。
- `frontend/src/components/SidebarMenu.vue`：递归渲染菜单。
- `frontend/src/router/index.js`：路由守卫、权限检查、应用启动时刷新用户资料。
- 未知 component 使用 `Placeholder.vue`，避免整个菜单失效。

### 6.5 按钮权限

全局注册：

```text
v-permission
```

使用示例：

```vue
<el-button v-permission="'order:create'">提交报修</el-button>
<el-button v-permission.all="['order:read', 'order:update']">操作</el-button>
```

后端仍执行接口级权限校验，前端指令只负责展示控制。

## 7. 验证码设计

### 7.1 验证码类型

| 类型 | 实现 | 有效期 | 最大尝试 |
|---|---|---:|---:|
| 图形验证码 | Java AWT 生成 PNG data URI | 5 分钟 | 一次性 |
| 手机验证码 | Spug 短信 | 5 分钟 | 5 次 |
| 邮箱验证码 | SMTP | 5 分钟 | 5 次 |
| 微信扫码状态 | 内存扫码会话 | 3 分钟 | 一次性确认 |

验证码生成使用 `SecureRandom`。

### 7.2 发送冷却

| 渠道 | 限制 |
|---|---|
| 手机号 | 同一手机号 60 秒一次 |
| 邮箱 | 同一邮箱 60 秒一次 |
| 发送 IP | 每 IP 每分钟最多 5 次 |
| 登录 IP | 每 IP 每分钟最多 10 次 |
| 图形验证码 IP | 每 IP 每分钟最多 30 次 |
| 登录失败 | 连续 5 次锁定 10 分钟 |

### 7.3 验证码使用规则

- 验证码不能重复使用。
- 验证成功立即删除。
- 失败次数达到 5 次后删除。
- 发送失败时删除刚生成的验证码，避免“没收到短信但验证码仍有效”。
- 真实模式不向前端返回验证码。

## 8. Spug 真实短信

### 8.1 工具

- 第三方平台：Spug Push 短信模板。
- 请求方式：GET。
- 后端工具：`RestTemplate`。
- 配置项：

```properties
app.sms.mock=false
app.sms.spug.url=Spug模板地址
app.sms.spug.number=5
```

生产/本地真实配置建议放在不提交 Git 的本地文件中：

```text
backend/src/main/resources/application-local.properties
```

该文件已加入 `.gitignore`。

### 8.2 请求参数

```text
to      接收手机号
code    6位验证码
number  有效时长，默认5
```

只有 Spug 返回：

```json
{
  "code": 200,
  "msg": "请求成功"
}
```

才认为是发送成功。

### 8.3 重要注意事项：IP 白名单

Spug 短信模板可能启用了 IP 白名单。

出现以下错误时：

```text
请求IP: x.x.x.x 不在IP白名单内
```

说明不是短信余额问题，而是服务器/本机公网出口 IP 变了。

处理方式：

1. 登录 Spug 控制台。
2. 进入当前短信模板的配置。
3. 找到 IP 白名单。
4. 添加当前网络公网出口 IP。
5. 保存后重新发送。

使用手机热点时公网 IP 可能变化，因此每次切换网络后可能需要重新添加。

### 8.4 短信额度

Spug 免费/试用短信额度用完后，也会拒绝发送请求。

常见原因：

- 免费额度已消耗。
- 充值到了账户余额，但短信模板额度未到账。
- 充值到了其他项目/模板。
- 短信通道有独立额度。
- 模板每次发送消耗的额度规则不同。

注意：应用侧的 60 秒冷却只能防止重复点击，不能绕过 Spug 平台额度。

## 9. 真实 SMTP 邮箱

### 9.1 当前实现

- 后端工具：Spring Mail `JavaMailSender`。
- 邮件服务器：QQ 邮箱 SMTP。
- 端口：465。
- 加密方式：SSL。
- SMTP 密码使用邮箱授权码，不是 QQ 登录密码。

真实配置同样放在不提交 Git 的本地配置中：

```properties
app.email.mock=false
app.email.from=发件邮箱
spring.mail.host=smtp.qq.com
spring.mail.port=465
spring.mail.username=发件邮箱
spring.mail.password=SMTP授权码
spring.mail.properties.mail.smtp.auth=true
spring.mail.properties.mail.smtp.starttls.enable=false
spring.mail.properties.mail.smtp.ssl.enable=true
spring.mail.default-encoding=UTF-8
```

### 9.2 注意事项

- 不能把 SMTP 授权码提交到 Git。
- 发件邮箱通常必须与 SMTP 登录账号一致。
- QQ 邮箱需要先开启 SMTP 服务并生成授权码。
- 正式发件建议配置 SPF、DKIM、DMARC，降低进入垃圾箱的概率。
- 如果使用 587 端口，应使用 STARTTLS；465 端口使用 SSL。
- SMTP 认证失败和连接失败应分别提示，不能统一成“发送失败”。

## 10. 错误码与用户提示

统一响应示例：

```json
{
  "code": 503,
  "message": "短信服务额度已用完，请联系管理员充值后再试",
  "data": {
    "errorCode": "SMS_QUOTA_EXHAUSTED",
    "channel": "SMS",
    "retryable": false
  }
}
```

### 10.1 Spug 错误分类

| 情况 | 错误码 | 用户提示 |
|---|---|---|
| 短信额度耗尽 | `SMS_QUOTA_EXHAUSTED` | 短信服务额度已用完，请联系管理员充值后再试 |
| IP 不在白名单 | `SMS_IP_NOT_ALLOWED` | 短信服务访问受限，请联系管理员检查服务器 IP 白名单 |
| Spug 平台频率限制 | `SMS_PROVIDER_RATE_LIMITED` | 短信平台触发频率限制，请稍后再试 |
| 模板/签名/通道异常 | `SMS_TEMPLATE_CONFIG_ERROR` | 短信服务配置异常，请联系管理员 |
| Spug 超时 | `SMS_PROVIDER_TIMEOUT` | 短信服务响应超时，请稍后重试 |
| Spug 不可用 | `SMS_PROVIDER_UNAVAILABLE` | 短信服务暂时不可用，请稍后重试 |

### 10.2 SMTP 错误分类

| 情况 | 错误码 | 用户提示 |
|---|---|---|
| SMTP 认证失败 | `EMAIL_SMTP_AUTH_FAILED` | 邮箱服务认证失败，请联系管理员 |
| SMTP 连接失败 | `EMAIL_SMTP_CONNECT_FAILED` | 邮件服务连接失败，请联系管理员 |
| SMTP 超时 | `EMAIL_SMTP_TIMEOUT` | 邮件服务响应超时，请稍后重试 |
| SSL/TLS 配置错误 | `EMAIL_TLS_CONFIG_ERROR` | 邮件加密配置异常，请联系管理员 |
| 收件人拒绝 | `EMAIL_RECIPIENT_REJECTED` | 该邮箱暂时无法接收验证码 |
| 邮件内容异常 | `EMAIL_MESSAGE_INVALID` | 邮件内容配置异常，请联系管理员 |

### 10.3 前端展示原则

- 优先展示后端 `message`。
- 不再展示 HTTP 状态码和接口地址给普通用户。
- `423` 展示锁定倒计时。
- `429` 展示剩余冷却秒数。
- `503` 展示服务配置或额度问题。
- 未知异常显示统一友好提示，详细信息只写入后端日志。

## 11. 反爬与安全措施

已实现：

- 登录 IP 限流。
- 图形验证码 IP 限流。
- 短信/邮箱目标账号 60 秒冷却。
- 发送 IP 每分钟限制。
- 验证码最大尝试次数。
- 验证码一次性消费。
- JWT jti + 服务端会话。
- 客户端指纹绑定。
- refresh Token 轮换和重放检测。
- 账号锁定后会话立即吊销。
- 权限变更后会话立即吊销。
- 登录、锁定、解锁、退出、权限变更审计。

当前限制：

- 验证码和频率限制目前是单实例内存实现。
- 多 Tomcat 节点部署时，应把验证码、冷却和 IP 限流迁移到 Redis。
- 数据库会话和账号锁定已落库，可以跨节点共享。

## 15. 常见问题排查

### 15.1 后端控制台马上退出

常见原因：

- 8081 端口已被另一个后端进程占用。
- MySQL 服务未启动。
- `JAVA_HOME` 未正确指向 JDK 17。

### 15.2 邮箱仍然显示模拟验证码

原因通常是旧后端进程仍在运行，未加载新的本地配置。

处理：

1. 停止旧后端。
2. 确认 `application-local.properties` 存在。
3. 重新启动后端。
4. 发送验证码时响应数据不应包含 `mockCode`。

### 15.3 短信提示 IP 白名单

原因：当前网络出口 IP 变化。

处理：

1. 在 Spug 控制台查看当前模板 IP 白名单。
2. 添加当前公网出口 IP。
3. 切换网络后重新检查。
4. 不建议通过代码绕过平台白名单。

### 15.4 短信提示额度不足

原因：Spug 平台短信额度耗尽或充值未到当前模板/通道。

处理：

1. 检查 Spug 短信额度。
2. 确认充值项目和模板。
3. 等待额度同步。
4. 不要改回 mock 模式掩盖真实问题。

### 15.5 启动时提示端口占用

在 PowerShell 查看：

```powershell
netstat -ano | Select-String ':8081'
```

确认占用进程后停止旧后端，再重新启动。

## 16. 部署与配置注意事项

1. JWT 生产密钥必须通过 `JWT_SECRET` 覆盖，不能使用默认值。
2. SMTP 授权码、Spug 模板地址、数据库密码不能提交 Git。
3. 本地真实配置放在被忽略的 `application-local.properties`。
4. MySQL 服务需保持运行。
5. 真实短信要注意 Spug 额度和 IP 白名单。
6. 真实邮箱要注意 SMTP 授权码、端口和 SSL/TLS 配置。
7. 多实例部署时，验证码和限流应迁移到 Redis。
8. 前端请求必须保持相同的 `X-Client-Fingerprint`。
9. 权限变更后必须让受影响用户重新登录，旧 Token 已吊销。
10. 不要把前端隐藏按钮当作安全措施，后端接口校验才是最终边界。
