# 开发规范

> 依据：课程《项目总体设计——技术、应用、安全与数据架构》、《前后台项目代码规范监测组件配置说明》、《阿里巴巴 Java 开发手册（1.3.1）》。
> 架构原则：前后端分离；每人负责一个功能模块，前端 + 后端均由本人完成。

## 1. 代码管理（Git）

### 1.1 分支管理

| 分支 | 说明 |
|------|------|
| `main` | 主分支，稳定可运行的代码 |
| `feature/功能名` | 功能分支，用于开发新功能 |

- 禁止直接在 `main` 上开发
- 功能分支命名：`feature/智能报修`、`feature/自助诊断`
- 新功能从 `main` 上 `checkout` 出来

### 1.2 提交规范

- 提交信息使用中文，格式：`type(模块): 描述`
- 示例：
  - `feat(报修): 增加智能报修表单`
  - `fix(调度): 修复派单冲突检测 bug`
  - `docs: 更新API文档`
  - `refactor(评价): 重构评价逻辑`

### 1.3 合并规范

- 功能完成后发起 Pull Request（PR）合并到 `main`
- PR 至少由一名其他成员 review 通过后方可合并
- 合并前需确保代码可运行、无冲突

## 2. 前端规范（ESLint 监测）

### 2.1 组件与工程约定

- 使用 Vue 3 **组合式 API**（`<script setup>`）
- 路由统一在 `src/router/index.js` 中注册
- 组件命名：多个单词组成，首字母大写（如 `RepairForm.vue`）
- 公共组件放在 `src/components/` 下，页面组件放在 `src/views/`
- UI 统一使用 Element Plus，图标使用 `@element-plus/icons-vue`
- API 请求统一封装，使用 `axios`，不允许在页面中直接散写 `axios.get`
- 缩进统一 2 个空格

### 2.2 ESLint 配置（代码规范监测组件）

- 配置文件：`frontend/.eslintrc.cjs`
- 依赖：`eslint@8`、`eslint-plugin-vue@9`（已装入 `frontend/node_modules`）
- 已启用规则：`quotes`（单引号）、`semi`（必须分号）、`eqeqeq`（全等）、`curly`、`camelcase`、`no-unused-vars`、`no-console`（warn）、`no-debugger` 等，并启用 `plugin:vue/vue3-recommended`
- 若 eslint 刚配置好，先用一个简单 JS 文件自测是否生效

### 2.3 使用方法

```bash
cd frontend
npm run lint          # eslint src --fix   自动修复基础错误（如引号、分号）
npm run lint:check    # eslint src         只检查、不修改
```

- `--fix` 只能修复不影响逻辑的基础错误（引号、分号、多余空格等），像 `no-unused-vars` 这类需手动修改
- 提交前必须 `npm run lint` 无 error

## 3. 后端规范（Alibaba Java Coding Guidelines）

### 3.1 分层与包结构

- 分层结构：`Controller` -> `Service` -> `Repository`
- 包名统一为 `com.example.campusrepair`，按模块分包
  - `controller` 接口层
  - `service` 业务层
  - `repository` 数据访问层
  - `entity` 实体类
  - `dto` 数据传输对象
  - `config` 配置类
- RESTful 接口风格，返回统一 JSON 格式 `{ code, message, data }`
- 数据库操作使用 Spring Data JPA（参数化查询，禁止字符串拼 SQL）

### 3.2 阿里插件安装与使用（IDEA）

1. `File -> Settings -> Plugins`，搜索 `alibaba`，安装 **Alibaba Java Coding Guidelines**
2. `Tools -> 阿里编码规约 -> 开启实时监测功能`（默认开启），问题处自动标红/黄
3. 扫描结果分三个等级：Blocker（崩溃）、Critical（严重）、Major（主要）
4. `File -> Settings -> Inspections -> ali-check` 可勾选/取消某项检查
5. 部分问题可用 `Alt + Enter` 直接更正

> 插件目录说明：IDEA 插件默认装在用户目录（C 盘）。如要求全部安装不落在 C 盘，可在 IDEA 的 `idea.properties` 中把 `idea.plugins.path` 指向 D 盘目录（如 `D:\IDEA-Plugins`）后重启。

### 3.3 类注释模板（IDEA）

`File -> Settings -> Editor -> File and Code Templates -> Files`，修改 `Class` / `Interface`：

```
/**
 * @Description //TODO 类的功能说明
 * @Author ${USER}
 * @Date ${DATE} ${TIME}
 * @Version 1.0
 */
```

- `${NAME}`：类名
- `TODO`：随类一起生成，见下
- `${USER}` / `${DATE}` / `${TIME}`：创建人、创建日期、时间（IDEA 内置变量）
- 所有类必须添加创建者和创建日期（阿里规约【强制】）

### 3.4 方法注释模板（IDEA Live Template）

`File -> Settings -> Editor -> Live Templates`：新建组 `userDefine`，新建模板 `*`，应用场景选 `Everywhere -> Java`，内容：

```
 *
 * @Description //TODO $end$
 * @Param $param$
 * @return $return$
 * @Author ${USER}
 * @Date $date$ $time$
 **/
```

- 注意第一行只有一个 `*`，不要写 `/ *`
- 参数名必须用 `${参数名}$` 形式，否则读不到
- 在 `Edit variables` 中为 `$param$`、`$return$`、`$date$`、`$time$` 配置对应获取方法
- 使用方法：在方法上方输入 `/** + Enter`

### 3.5 阿里编码规约要点（节选，开发时遵守）

- 命名：类名 UpperCamelCase；方法/变量 lowerCamelCase；常量全大写 + 下划线；包名全小写单数
- 禁止魔法值出现在代码中；`Long` 赋值用大写 `L`
- 4 个空格缩进，禁止 tab；单行不超过 120 字符
- POJO 类属性一律用包装类型，必须写 `toString()`；DO/DTO/VO 不设默认值
- 覆写方法必须加 `@Override`；Service/DAO 暴露接口，实现类以 `Impl` 结尾
- `if/else` 嵌套不超过 3 层，多用卫语句 / 策略模式
- 循环内字符串拼接用 `StringBuilder.append`；不在 foreach 中 remove/add
- 日志统一使用 SLF4J，占位符输出：`logger.debug("id={}", id);`，不打印敏感信息
- 类、方法、属性注释使用 Javadoc；方法内部单行注释用 `//`

## 4. 数据库规范（阿里巴巴 MySQL 规约）

### 4.1 约定

- 表名字段名：小写字母 + 下划线，不使用复数，不以数字开头，禁止保留字（`desc`、`order` 等）
- 布尔字段必须 `is_xxx` 命名，类型 `unsigned tinyint`（1 是 / 0 否）
- 小数用 `decimal`，禁止 `float` / `double`
- ID 类型为 `unsigned bigint`，单表自增、步长为 1
- 不建外键、不使用级联，外键约束在应用层解决（JPA 关联由代码维护）
- 禁止 `SELECT *`，需要哪些字段必须明确写出
- 禁止存储过程；删除/订正数据必须先 `select` 确认
- 更新记录时必须同步更新 `gmt_modified`

### 4.2 必备三字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | unsigned bigint | 主键，自增 |
| `gmt_create` | datetime | 创建时间 |
| `gmt_modified` | datetime | 更新时间 |

### 4.3 索引命名

- 主键索引：`pk_字段名`
- 唯一索引：`uk_字段名`
- 普通索引：`idx_字段名`

### 4.4 建表示例

```sql
CREATE TABLE `repair_order` (
    `id`           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '工单ID',
    `order_no`     VARCHAR(32)  NOT NULL COMMENT '工单编号',
    `is_deleted`   TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '是否删除: 1是/0否',
    `gmt_create`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `gmt_modified` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_order_no` (`order_no`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='报修工单表';
```

## 5. 安全规范

- 密码使用 BCrypt 哈希存储，绝不存明文
- 所有接口校验登录态与权限（RBAC：STUDENT/WORKER/ADMIN），只允许操作自己的数据（水平越权检查）
- 请求入参服务端全部校验（后端 `@Valid`），不信任前端
- 数据库操作用参数化查询 / JPA，杜绝字符串拼 SQL 防注入
- 日志不打印密码、手机号、身份证等敏感信息
- 密钥、数据库密码、API Key 不写入代码，用环境变量 / 配置文件，并核对 `.gitignore`
- 前端不向后端暴露的字段（如密码）做返回脱敏

## 6. 测试规范

- 每个功能完成后需自测通过
- 变更数据库、接口参数，需要先本地跑通再合入
- 接口使用 Postman/Apifox 测试，并在 `docs/api/` 记录接口文档
- 提交前运行单元测试：`cd backend && mvn test`

## 7. 文档规范

- 文档统一放在 `docs/` 目录下
- 接口变更必须同步更新接口文档
- 表结构变更先改 `docs/数据项设计.md` 再改脚本与代码
- 每周在 `docs/索引.md` 更新文档清单与进度（课程要求时另提交实施周报）

## 8. 提交前的自检清单

- [ ] 前端 `npm run lint` 无 error（ESLint 自动修复基础错误后仍有 error 的手动整改）
- [ ] 后端 IDEA Alibaba 插件扫描无 Critical 以上问题
- [ ] 代码本地运行通过，`mvn test` 通过
- [ ] 无调试残留代码（`console.log`、`System.out.println`、`debugger`）
- [ ] 无明文密钥、密码写入代码（走环境变量 / 配置文件）
- [ ] 已在本地完成主要流程测试
