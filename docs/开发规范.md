# 开发规范

## 1. 代码管理（Git）

### 1.1 分支管理

| 分支 | 说明 |
|------|------|
| `main` | 主分支，稳定可运行的代码 |
| `feature/功能名` | 功能分支，用于开发新功能 |

- 禁止直接在 `main` 上开发
- 功能分支命名：`feature/智能报修`、`feature/自助诊断`
- 新功能从 `main` 上 `checkout` 出来

### 1.2 提交规范

- 提交信息使用中文，格式：`type(模块): 描述`
- 示例：
  - `feat(报修): 增加智能报修表单`
  - `fix(调度): 修复派单冲突检测 bug`
  - `docs: 更新API文档`
  - `refactor(评价): 重构评价逻辑`

### 1.3 合并规范

- 功能完成后发起 Pull Request（PR）合并到 `main`
- PR 至少由一名其他成员 review 通过后方可合并
- 合并前需确保代码可运行、无冲突

## 2. 前端规范

- 使用 Vue 3 **组合式 API**（`<script setup>`）
- 路由统一在 `src/router/index.js` 中注册
- 组件命名：多个单词组成，首字母大写（如 `RepairForm.vue`）
- 公共组件放在 `src/components/` 下，可选，页面组件放在 `src/views/`
- UI 统一使用 Element Plus，图标使用 `@element-plus/icons-vue`
- API 请求统一封装，使用 `axios`，不允许在页面中直接 `axios.get` 散写

## 3. 后端规范

- 分层结构：`Controller` -> `Service` -> `Repository`
- 包名统一为 `com.example.campusrepair` 下按模块分包
  - `controller` 接口层
  - `service` 业务层
  - `repository` 数据访问层
  - `entity` 实体类
  - `dto` 数据传输对象
  - `config` 配置类
- RESTful 接口风格，返回统一 JSON 格式 `{ code, message, data }`
- 数据库操作使用 Spring Data JPA
- 所有请求参数做校验（使用 `@Valid`）

## 4. 数据库规范

- 表名：小写下划线（如 `repair_order`）
- 字段名：小写下划线（如 `create_time`）
- 主键统一用 `id`，创建时间 `create_time`，更新时间 `update_time`
- 表结构变更需同步更新文档

## 5. 测试规范

- 每个功能完成后需自测通过
- 变更数据库、接口参数，需要先本地跑通再合入
- 接口使用 Postman/Apifox 测试，并在 `docs/api/` 记录接口文档

## 6. 文档规范

- 文档统一放在 `docs/` 目录下
- 接口变更必须同步更新接口文档
- 每周在 `docs/索引.md` 更新文档清单与进度（课程要求时另提交实施周报）

## 7. 提交前的自检清单

- [ ] 代码本地运行通过
- [ ] 前端 `npm run build` 无报错
- [ ] 后端 `mvn compile` 无报错
- [ ] 无调试残留代码（print、console.log）
- [ ] 无明文密钥、密码写入代码
- [ ] 已在本地完成主要流程测试
