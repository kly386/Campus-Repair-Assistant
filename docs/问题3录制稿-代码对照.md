## 二、代码讲解段 55 秒 · 逐句对照（顺序即切窗口顺序）

| 台词（约） | 切到窗口 | 高亮位置 | 要说的要点 |
|---|---|---|---|
| "断点续传本质：记下断点在哪，恢复时从断点接着来" | `Files.vue` | L120-121 两个断点变量 | 断点状态就两个变量：`bigUploadId`（OSS 分片会话 ID）和 `bigNextIndex`（下一片下标），都存在前端会话里 |
| "初始化时后端生成 uploadId，存进分片会话表" | `Files.vue` → `FileStorageServiceImpl.java` | 前端 L147-150 → 后端 L174-177 | 前端没有 `bigUploadId` 说明是首次才调 `initMultipart`；后端 `ossClient.initiateMultipartUpload` 生成 uploadId，放进 `multipartSessions` 这个 ConcurrentHashMap 会话表（L74） |
| "每个分片成功后 OSS 落一份数据，都追加到同一个 uploadId 会话" | `FileStorageServiceImpl.java` | L188 → L197-199 | 每次 `uploadChunk` 都用同一个 uploadId 从会话表取出 objectKey，把每片转发进 OSS 该会话——这是断点续传可行的底层保证 |
| "恢复上传时拿同一个 uploadId 从未传分片开始追加，已传分片完全不重来，最后 complete 合并" | 回 `Files.vue` | L153 循环起点 + L163 `uploadChunk` + L166 `completeMultipart` | 三个动作连讲：从 `bigNextIndex` 起循环 → 用原 uploadId 调 `uploadChunk` 追加 → 全传完才调 `completeMultipart` 通知 OSS 合并重组 |
| "下载走标准 HTTP Range：请求头带 'Range: bytes=已下载字节数-'，服务器从此偏移量返回剩余内容" | 浏览器下载面板（或留在 `Files.vue` 的 `onDownload`） | （浏览器行为 + OSS 原生） | 应用不自己实现 Range 服务端——文件在 OSS 上，续传 Range 请求由浏览器发出、由 OSS 原生响应，我们只负责那层"签名授权" |
| "签名有效期通过 url-expire-seconds 配置（30 分钟）" | `application.properties` | L30 `aliyun.oss.url-expire-seconds=1800` | 顺带防盗链：签名 30 分钟过期 |
| "两套机制配合，大文件'传一半断网/下载一半中断'都有容错能力" | 保持全景 | — | 收束一句话，准备交接 |
